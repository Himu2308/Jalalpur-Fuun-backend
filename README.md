# Jalalpur Fun Ticketing — Backend

Node.js + Express + raw SQL (pg, no ORM) + PostgreSQL + Redis (for session revocation).

## Setup

1. `cp .env.example .env` and fill in real values (DB URL, Redis URL, Google client id, Razorpay test keys, JWT secret, admin password).
2. `npm install`
3. Create the Postgres database referenced in `DATABASE_URL`, then run `npm run migrate` to create tables and seed the game catalog.
4. Make sure Redis is running and reachable at `REDIS_URL`.
5. `npm run dev` (auto-restarts on file changes) or `npm start`.

## Auth model

Three separate kinds of session, all JWT + Redis-backed (see "Sessions" below):

- **Customers** log in with Google (`POST /auth/google`) + a one-time phone capture.
- **Workers** log in with just a UID, no password (`POST /auth/worker-login`) — a worker's UID and assigned activity (`role`, a game key) are created by an admin via `POST /staff`. A worker can only scan tickets for their assigned game.
- **Admin** is a single shared password (`ADMIN_PASSWORD` env var, `POST /auth/admin-login`) — there are no individual admin accounts. Admin can create/list workers, force-logout a worker's sessions, scan and validate a ticket for *any* game, and see the recent scan log.

Because admin has no per-person identity, a ticket scanned via the admin session records `scanned_by_staff_id = NULL` (shown as "Admin" in the scan log) — every other scan is attributed to a specific worker's UID.

## Sessions

Each login issues a JWT, but the JWT alone isn't enough to stay logged in — it carries a session id (`sid`) that must also exist in Redis (`session:<sid>`, one key per active login). This means:

- Logging out (`POST /auth/logout`, `POST /auth/worker-logout`, or `POST /auth/admin-logout`) deletes just that one session/device.
- An admin can force-logout every device for a worker at once via `POST /staff/:id/revoke` — use this when a UID is compromised or a worker leaves.
- If Redis is unreachable, all authenticated requests fail closed (401), and the server refuses to start.

## Routes

- `POST /auth/google` — customer login via Google ID token
- `POST /auth/phone` — save customer phone number (requires user auth)
- `POST /auth/logout` — end the current customer session (requires user auth)
- `POST /auth/worker-login` — worker login via UID only
- `POST /auth/worker-logout` — end the current worker session (requires worker auth)
- `POST /auth/admin-login` — admin login via the shared `ADMIN_PASSWORD`
- `POST /auth/admin-logout` — end the current admin session (requires admin auth)
- `GET /games` — list active activities
- `POST /games` — admin adds a new activity: name, price per person, and an image URL (requires admin auth; the internal `key` is auto-generated by slugifying the name)
- `POST /bookings` — create a multi-game cart booking + Razorpay order (requires user auth)
- `POST /bookings/:id/verify-payment` — verify payment, generate QR tickets (requires user auth)
- `GET /bookings/mine` — list logged-in user's bookings + tickets
- `POST /tickets/scan` — scan/validate a ticket QR (requires worker or admin auth; workers are limited to their assigned game, admin can scan any)
- `POST /staff` — admin creates a worker account: UID + name + assigned game (requires admin auth)
- `GET /staff` — admin lists worker accounts (requires admin auth)
- `POST /staff/:id/revoke` — admin force-logs-out every session for a worker (requires admin auth)
- `GET /staff/scans` — admin views the last 100 scans (activity, who scanned it, when) (requires admin auth)
